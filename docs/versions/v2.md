# V2 — "Modern GUI with drag-and-drop mappings"

## Goal

Replace the Tkinter GUI with a beautiful, modern, cross-platform desktop app (pywebview + React + Tailwind) that makes folder mapping a drag-and-drop visual task. Distributable as `pip install` on Day 1 and as `.dmg` / `.exe` on GitHub Releases shortly after. The core library (`granola_sync`) stays unchanged and backward-compatible.

## Success criteria

- [ ] Non-developer path: download the app → paste API key once → see Granola folders auto-populate → drag one onto a local path → sync.
- [ ] Setup → first successful sync in **under 2 minutes** for a new user.
- [ ] Library API from V1 still works unchanged (`import granola_sync` + existing function calls).
- [ ] Side-by-side tree view: Granola folders (left) ⟷ local filesystem (right).
- [ ] Drag-and-drop to create a mapping; delete mapping via right-click or explicit button.
- [ ] Per-mapping extraction config: "AI notes only" / "transcript only" / "both" (at minimum).
- [ ] Dark mode, rounded corners, hover states, smooth transitions — the app feels like Linear or Raycast, not like tkinter.
- [ ] Packaged as `pip install granola-sync` with `granola-sync` CLI launching the GUI.
- [ ] Packaged as unsigned `.dmg` (macOS) and `.exe` (Windows) on GitHub Releases, with a README GIF for the Gatekeeper bypass.
- [ ] Homebrew cask at `homebrew-cask` so `brew install --cask granola-sync` works.

## Non-goals for V2

- Radial tree visualization — cool but not load-bearing; leave for the roadmap.
- Scheduled auto-sync → roadmap.
- Search across synced notes → roadmap.
- Multi-account → roadmap.
- Signed `.dmg` with Apple Developer certificate — defer until we have users complaining about Gatekeeper. See [ADR on ad-hoc vs $99/yr](../decisions/0001-use-pywebview-for-v2-gui.md) rationale.

## Constraints / invariants

- Library public API from V1 is **frozen** — must stay backward compatible.
- API keys never leave the user's machine (same as V1). See [ADR-0002](../decisions/0002-local-only-no-saas.md).
- Two toolchains in the repo is OK: `src/granola_sync/` (Python) and `frontend/` (Node + Vite + React + TypeScript).
- Frontend talks to Python only via the pywebview JS ↔ Python bridge — no local HTTP server to spin up.
- No telemetry / analytics.

## Subversions

Created only when work starts — filenames appear in this directory only once that subversion is the active cut. Planned cut points (rough, subject to change):

- [x] **v2.1** — React frontend scaffold; pywebview bridge; feature parity with existing Tkinter GUI (API key save, folder discovery, mapping list, sync trigger).
- **v2.2** — Side-by-side tree views; drag-and-drop mapping creation.
- **v2.3** — Per-mapping extraction config; polish pass (animations, dark mode refinements).
- **v2.4** — PyInstaller packaging; `.dmg` / `.exe` on GitHub Releases; Homebrew cask submission.

## Open questions

- **Frontend state management**: Zustand vs Context + `useReducer`? Defer until v2.1 makes it obvious.
- **Sync progress streaming**: pywebview `evaluate_js` callbacks from a Python thread, or JS-side polling of a status endpoint? Probably callbacks — decide in v2.1.
- **Filesystem tree**: lazy-load per folder expand, or upfront scan? Probably upfront for small trees (<10 k entries) and lazy for larger — profile in v2.2.
- **Tkinter GUI in V2**: delete it or keep as a fallback? Default plan is **delete** when V2 ships to avoid dragging along two UIs; revisit only if a user specifically needs it.
